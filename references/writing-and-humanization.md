# 最终语言处理与科学内容保护

## 必须实际使用 humanizer-zh

只要本技能生成或修改 Markdown 文档，就必须在内容完成后读取并遵循已安装的 `humanizer-zh`，不能仅在自检里写一句“已润色”。处理顺序固定为：

```text
论文理解 → 信息核验 → 科学分析 → 文档生成 → humanizer-zh → 最终自检
```

本次安装环境已确认的路径为 `C:/Users/Zihan/.agents/skills/humanizer-zh/SKILL.md`。优先使用当前会话技能目录提供的位置；该路径仅作本机后备。若移动环境导致缺失，在当前 Codex 全局技能位置和用户 `.agents/skills` 中查找同名技能。不要把 Claude 工具名或斜杠调用方式当作 Codex API；读取技能并用当前工具执行其适用规则即可。

若无法找到或读取真实技能，可继续科学内容工作，但明确语言处理步骤未完成，保留待处理状态，不声称已调用或用自编规则冒充。不要擅自安装来源不明的替代品。

## 与科研教学要求共同执行

遵循 humanizer-zh 去除填充短语、机械转折、宣传语、模糊归因、无意义排比、刻意换词和空泛结尾的规则。句式可自然变化，复杂内容仍要逐步讲清。保持专业术语一致，不为避免重复而换成意义不同的同义词。

本任务明确要求教学梯度、数学中间步骤和结构化证据。因此 humanizer 中“跳过手把手引导”“打破结构”“增加个性”等风格建议，只在不影响这些要求时适用。不得删掉必要解释、制造第一人称经历、加入幽默或情绪、增加事实细节，也不为避开三项列表而增删科学要点。

全文翻译必须保留原文意义、段落和限定。只改中文表达，不改因果强度，不把 suggest 改成 prove。原文就是重复表达时，不能为了润色删去原文段落。译者补充与译文正文分开。

## 实际处理步骤

1. 在语言处理前核对并保留关键事实清单：所有数字及单位、n 的定义、p/区间/效应量、公式与符号、引用标识符、图表号、来源标签、限定词及结论强度。长文分节处理，每节都对照原稿。
2. 逐段按 humanizer-zh 规则检查并修改有问题的中文叙述。无需为了表现“处理过”而改动已经自然、准确的句子。
3. 对照处理前文本及原始来源，核对上述事实项未改变、推导步骤未丢失、翻译没有合并漏段。公式、数据、代码块、Mermaid 结构和引用 URL 原则上不进入语言改写；发现内容错误应回到科学核验步骤修正并记入 correction log。
4. 对四份文件保持术语、结论强度、来源状态一致。图表和模型教学里的补充解释不能被润色成作者的结论。
5. 按 [SELF_CHECK.md](../SELF_CHECK.md) 复核。核验记录中简短记录读取的 humanizer 路径、处理范围、日期及事实保护核对结果；只有完成的步骤才记为完成。

把篇幅用在解释问题、推导、测量和证据上。删去“具有重大意义”一类空泛评价，保留“不确定”“在这些条件下”等影响结论的限定。
